## 4. 风险

再次创建的主要风险是：若当初的请求实际已经生成页面，而这次列表没有返回它，补录会产生第二页。当前完整列表的页数和上次验收相同，这 7 个词头和稳定 ID 都不在其中，这种可能已经变小，但原始响应确实没有拿到，所以不能把它写成确定的失败。

其次，这 7 次中断都发生在前后词都成功的时候。一次把 7 个词连着创建，仍可能再出现同样的单请求中断，并再留下新的待对账词。

空白页与这 7 个词没有对应关系。补录时不能用它顶替任何一个词，也不能删除它。
