# 本地数据恢复与回滚约定

正式应用当前打开 schema v3。P2-B1 的 schema v4 只能用于带隔离标记的副本；不能把它或模拟测试数据库恢复为个人正式库。

迁移、写入或换设备前，通过只读连接与 SQLite backup API 生成独立、一致的备份，记录备份文件校验值，检查 integrity_check、foreign_key_check、schema 版本、词数及稳定 ID。原数据库与 backup 文件的字节哈希可能不同，应分别记录并逐表核对，不能只看文件哈希判断内容是否相同。

备份只通过个人可信方式携带，不进入公开仓库或 Release。恢复前关闭应用并保留目标设备已有数据库；确认实际应用支持目录后再恢复，不根据旧电脑的重定向物理路径猜测新路径。

副本迁移在事务中完成。任何 DDL、版本设置、事件或队列写入失败，都应回滚整个本地事务，不删除数据库重建，不只保留其中部分记录。学习事件与进度必须一起保存，旧版缺少的历史时间或次数不得推算。

只读词库同步失败保留本地数据，内容更新不覆盖词义、发音及复习日期。未来写入遇到远端结果不明时，保留稳定事件 ID 与 uncertain/sending 状态，先对账，不能直接重建事件。软件回滚和恢复旧数据库不会撤销已经发生的云端写入。

Windows 系统凭据和 Android Keystore 不属于 SQLite 备份，换设备需另行安全授权。没有明确授权时，不创建正式事件库、不上传真实事件、不把模拟事件混入个人历史。

当前实施状态与范围以 [DEVICE_HANDOFF.md](DEVICE_HANDOFF.md) 为准。
